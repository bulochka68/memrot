## Вариант для слайда (основной)

**Заголовок:** Продуктовая ценность

**Подзаголовок:** Превращаем «агент повёл себя странно» в воспроизводимую находку
с доказательством — и в регрессионный тест.

| | |
|---|---|
| **Видим то, чего не видит классический пентест** | Не «проверим промпт», а жизненный цикл агентной системы: память, инструменты, IAM, хопы сервис→сервис. 28 правил в общем словаре `MEM / AUTH / TOOL / EGRESS / INFRA / INV`. |
| **Доказательство вместо процента** | У каждого утверждения свой источник, метод, статус и ссылки на свидетельства. Отчёт идёт на security review как артефакт, а не как «так сказала модель». |
| **Три ступени подтверждения** | `static_path_supported → runtime_path_observed → control_violation_observed`. Отличаем «дефект в конфиге» от «данные чужого клиента реально утекли». |
| **Честная метрика** | ASR не выдумывает знаменатель: пробел (`NOT_EVALUATED` / `ERROR`) никогда не выдаётся за «чисто». |
| **Дёшево на входе** | Offline-аудит ничего не поднимает и никуда не ходит; атаки идут только туда, куда указал аудит (ranked по severity). |
| **Переносится данными** | Новый агент = профиль + манифест + адаптер (~40 строк). Движок не трогаем — доказано переносом на чужую систему MemPalace. |
| **Живёт в CI** | `--gate` возвращает exit code, есть baseline/drift. Режим `protected` — регрессия: те же атаки обязаны позеленеть. |

## Что заказчик получает на выходе

- **Отчёт аудита** `agent-security-audit` 2.0 — JSON · Markdown · JSONL · ObSec.
- **Список находок** с `rule_id`, severity, провенансом и явным перечнем того,
  что осталось непроверенным (`limitations`, `coverage`).
- **Результат атак** `run.json` + HTML-дашборд: verdict по каждой попытке и
  `path_state` по каждой цели.
- **Exit code для пайплайна** — гейт перед релизом, а не PDF «на почитать».

## Кому и зачем

| Кто | Что закрывает |
|---|---|
| SECDEV / AppSec | Гейт перед релизом агента: артефакт с провенансом вместо ручной переписки с ботом. |
| Продуктовая команда | Регрессия при добавлении нового тула или уровня памяти — новый вектор виден сразу. |
| Обучение / демо | Стенд с переключателем `vulnerable` / `protected`: одна и та же атака красная и зелёная. |

## Чем мы отличаемся

Сканеры промптов (garak, promptfoo) проверяют **модель**. Мы проверяем **агентную
систему**: память, которая переживает сессию и утекает к следующему пользователю;
инструменты, чей вывод превращается в инструкции; авторизацию, делегированную LLM.
Чужие банки джейлбрейков при этом импортированы как отдельная ось ASR — мы их
дополняем, а не заменяем.

Честная граница: аудит — это **диагностика, а не защита**. Статическое
подтверждение показывает дефект кода или конфигурации, рантайм-подтверждение
привязано к наблюдённому принципалу и сборке. Мы это пишем в отчёте, а не прячем.

## Заметки докладчика (~30 секунд)

Сегодня команда, которая выкатывает GenAI-агента, не может ответить на вопрос
«он безопасен?» ничем, кроме ручной переписки в чате. Классический пентест не
видит агентную поверхность, а LLM-сканер отдаёт процент без доказательства.

Мы даём петлю: аудит статикой находит гипотезы с провенансом, атаки рантаймом
переводят их в наблюдаемое нарушение, оба конца говорят на одном словаре правил.
На выходе — не «оценка безопасности», а конкретная находка: какое правило, каким
свидетельством подтверждено, до какой ступени доведено и что осталось непроверенным.
И это ставится в CI, а режим `protected` доказывает, что фикс закрыл именно тот
дефект, который мы нашли.

## Сжатая версия (если слайд один и времени мало)

**Продуктовая ценность**

1. **Находим то, что не ловит пентест** — память, инструменты, IAM агента; 28 правил в одном словаре.
2. **Доказываем, а не оцениваем** — провенанс у каждого утверждения, три ступени подтверждения, честный ASR.
3. **Ставим в конвейер** — offline-аудит бесплатен, атаки ранжированы по находкам, `--gate` в CI, перенос на нового агента — данными.
